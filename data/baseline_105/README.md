# ESG 碳治理能力基准库 · 原始数据

> 本目录存放「行业基准库」建设所用的**全部原始提取结果**，用于回答一个问题：
> **"你们的对标基准，是拿什么数据算出来的？"**

## 一、这批数据是什么

对样本企业的 2025 年度原生 ESG 报告（PDF），用本系统的**生产提取链路**逐份提取
碳治理信息（4 维度 / 39 个 L3 子域 / **42 个 L4 指标**），并做**确定性算分**后得到的结构化 JSON。

| 项 | 说明 |
|---|---|
| 样本来源 | 资料库中 105 个旧提取结果文件 → 去重后 **93 家公司** |
| 输入 | 93 份原生 ESG 报告 PDF（中文 73 份 / 英文 19 份；纳思达 1 家缺原始报告） |
| 提取方式 | 线上生产链路（DeepSeek 结构化抽取），**非**本地离线脚本 |
| 算分方式 | `weights_logic.py`（Python 确定性计算，**无 LLM 参与**） |
| 口径版本 | 生产同源，`conf_version` = **v119b**（见 `manifest.json`） |
| 权重来源 | AHP 词频 → 1/3/5/7/9 映射（**与本目录数据无关，未随本次重算变动**） |

## 二、数据准备与映射结论（`manifest.json`）

105 个旧提取结果文件里含 **11 组重复副本**（同一公司的两次提取，如 `(2)` 后缀、
`亿华通` / `北京亿华通科技股份有限公司` 两种写法），去重后为 **93 家公司**。

| 统计项 | 值 |
|---|---|
| 旧提取结果文件 | 105 |
| 去重后公司 | **93** |
| 其中「德州联合石油」与「德石股份联合石油」实为同一家（已合并） | −1 |
| 已定位原始 PDF | **92** |
| 真缺原始报告 | **1**（纳思达股份有限公司） |
| 行业标签来源 | `行业分类清单.xlsx` 92 家 + 人工补丁 1 家 |
| 语言分布 | 中文 73 / 英文 19 |

> 行业分布（93 家）：电子科技 27、装备制造 12、化工新材料 12、消费制造 9、能源电力 9、
> 医药生物 8、建筑地产 6、环保水务 4、交通运输 3、金融业 3。

`manifest.json` 每行字段：`公司 / 行业 / 语言 / 原始 PDF 绝对路径 / 匹配方式 / 重复组 / 提取状态`。
其中「匹配方式」中 `manual` 表示 PDF 文件名只有简称（如"天禾股份"对应"广东天禾农资"），
经人工确认后写入白名单。

## 三、目录结构

```
baseline_105/
├── README.md            ← 本文件

```

## 四、为什么要重做（口径一致性）

上一版基准库（`weights.json`）由 `build_baseline.py` 生成，其判分规则是
**按提取结果里的「数据类型」字段**（定量=3 / 定性=2 / 其他=0），
而线上评分用的是**按字段内容自判**（值是否含数字、是否多年、是否未披露）。

两套口径在同一批历史数据上实测差异：

| 口径 | 加权基础分 Σ |
|---|---|
| 上一版基准库（记录值） | 1.931 |
| 旧口径（按`数据类型`重算） | 1.962 |
| **现行口径（线上在用）** | **3.075** |

结论：旧基准库与现行口径**不同源**（差 +1.11），导致"企业分低、基准也低"的双边失真。
本目录即用现行口径**在提取层重跑一遍**，使基准库与企业评分**同源可比**。

此外，重跑同时修复了三处提取/判定层缺陷（版本 **v119b**）：

| 缺陷 | 修复 |
|---|---|
| 超长文本**从头截断** 6 万字符（英文报告中位 24 万字符，只能覆盖前 24%） | 改为「头部连续保留 + 后半全篇抽样」，预算 12 万字符 |
| 提示词内部冲突（枚举值只许中文 ⟂ 一律用报告主体语言） | 受控枚举固定简体，仅「原文」随报告语言 |
| 判定词只认简体中文（繁体"未揭露"、英文 "Not disclosed" 挡不住） | 补繁简归一（zhconv）与英文等价式 |

## 五、复现方式

```bash
# 1. 生成映射清单（105 文件 → 93 公司 → 92 份 PDF）
python scripts/make_manifest.py

# 2. 批量提取（走生产 API，断点续跑）
python scripts/batch_extract_105.py --manifest manifest.json --out raw_json/

# 3. 重建基准库（现行口径）
python scripts/build_baseline_v2.py --raw raw_json/ --out excel/
```

## 六、审计线索

- 每份 JSON 含 `报告元数据`（公司名、报告期）+ `指标提取结果`（42 项，每项含 `值`/`年份`/`原文`）
- `原文` 字段是**报告中的原句摘录**，可回溯到原始 PDF 核对
- 本批数据受 **v118+ 证据强制校验**约束：得分指标的 `原文` 必须能在报告全文中定位，
  定位不到者自动降级为"未披露"（防幻觉）
- `manifest.json` 的 `extract_build` 字段记录提取时生产链路的实际版本
